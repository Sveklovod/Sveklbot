# SvekloBot

Музыкальный Discord-бот на Python: локальные аудиофайлы, плейлисты-папки,
панель с кнопками и выбором песен, пауза, переключение и громкость.
Список команд доступен через `/help`, панель — через `/player`.

## Содержимое

- `bot.py` — код бота.
- `requirements.txt` — версии библиотек.
- `Dockerfile` — Python 3.11, FFmpeg, ffprobe и Opus для Linux.
- `.env.example` — пустой пример настроек.
- `music/test-tone.wav` — негромкий тестовый сигнал длительностью 3 секунды.

Настоящего токена, логов и личной музыки в этом репозитории нет.
При публичной загрузке код и тестовый сигнал будут доступны всем.

## Создание репозитория на GitHub

1. Создай репозиторий `sveklobot` в своём аккаунте.
2. Для простого подключения по обычной ссылке выбери Public.
   Приватный репозиторий требует отдельной настройки доступа на хостинге.
3. README, лицензию и .gitignore на странице создания можно не добавлять:
   нужные файлы уже подготовлены.
4. На странице пустого репозитория нажми `uploading an existing file`.
5. Загрузи содержимое этой папки, включая файлы с точкой в начале имени
   и папку `music`. Саму внешнюю папку `sveklobot-github` загружать не нужно.
6. Нажми `Commit changes`. Файлы `bot.py`, `requirements.txt` и `Dockerfile`
   должны быть видны сразу в корне репозитория, в ветке `main`.

Если пользуешься архивом, сначала распакуй его. GitHub не распаковывает
загруженный ZIP в файлы репозитория.

## Настройки Bothost

| Поле | Значение |
| --- | --- |
| Название | SvekloBot |
| Платформа | Discord |
| Язык / версия | Python / 3.11 |
| Локация | Нидерланды |
| Bot Token | Существующий токен бота, вводится только в панели хостинга |
| Git URL | HTTPS-ссылка на твой репозиторий |
| Ветка | main |
| Главный файл | bot.py |
| Использовать домен | Выключено |
| Использовать собственный Dockerfile | **Включено** |

Собственный Dockerfile нужен для установки системных FFmpeg и Opus.
Он содержит проверку загрузки Opus во время сборки. Одного копирования
Windows-файла `ffmpeg.exe` на хостинг недостаточно.

В переменных окружения:

- `DISCORD_GUILD_ID` — тот же числовой ID сервера, что в локальном `.env`.
  Он сохраняет регистрацию команд на сервере и предотвращает создание
  отдельного глобального набора.
- `MUSIC_DIR` — `music` для первого теста.

Bothost передаёт Discord-токен из поля Bot Token в `DISCORD_TOKEN`.
Рабочий `.env` с компьютера загружать в GitHub не нужно.
`FFMPEG_PATH` оставь незаданным: FFmpeg будет найден в Linux автоматически.

## Первая проверка

1. Перед запуском на хостинге останови локального бота через Ctrl+C.
2. Дождись сборки и проверь логи запуска. Должна появиться строка «Бот запущен».
3. Зайди в голосовой канал, вызови `/player` и нажми «Пуск».
4. В плейлисте «Без папки» прозвучит короткий тестовый сигнал.

Docker-образ нужно собрать и проверить на самом хостинге: локально Docker
при подготовке этих файлов был недоступен. Проверка на компьютере не
подтверждает качество сети, лимиты ресурсов и звук в Discord на хостинге.

## Добавление своей музыки

Для постоянного хранения используй папку `data`, которую Bothost сохраняет
при обновлении проекта из Git. После успешного теста:

1. В файловом менеджере хостинга создай `data/music`.
2. Загрузи в неё песни и подпапки-плейлисты, например:

   ```text
   data/music/
   ├── Таверна/
   ├── Бой/
   └── Спокойная музыка/
   ```

3. Измени переменную `MUSIC_DIR` на `data/music` и перезапусти бота.
4. Открой `/player` и выбери плейлист.

Перед загрузкой коллекции проверь объём диска на тарифе и лимит размера
файлов в панели. Файлы из `data` не добавляются в GitHub.
`.gitignore` дополнительно исключает личную музыку, кроме тестового сигнала.
При ручной загрузке через сайт GitHub выбирай только подготовленные файлы:
правила `.gitignore` не заменяют проверку списка загружаемых файлов.
